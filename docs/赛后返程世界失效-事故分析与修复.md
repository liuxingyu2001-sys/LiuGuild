# 赛后返程世界失效：事故分析与修复

> 事故日期：2026-10-18 20:00 起（fb 服），症状持续到 2026-10-21。
> 受影响玩家：`_Elio_OvO`（`78af915e-e154-3b28-a374-a6c2806e4d4a`）、`E_v` 等当晚在副本内被赛季混战报名/拉入的成员。
> 结论一句话：**LiuGuild 的赛季混战把「liudungeon 的副本实例世界」记成了赛后返程点，而实例世界用完即删——世界没了返程就永远失败，插件每 5 秒重试一次，于是刷屏、反复切服、玩家被传送封印卡住。**

---

## 1. 玩家看到的现象 ↔ 真实原因

| 玩家侧表现 | 实际发生的事 |

| 聊天里反复出现 `ld_dungeoncolosseum_25754e940a53485d9bbddd0a2546aa4e` | LiuGuild 每 5 秒发一次 `§c赛季返程世界未加载：<世界名>，保留返程记录。` |

| 10-18 20:03 一登录就 `fell out of the world` | 返程世界已删，代码把**旧世界坐标**套到了主世界 → 直接传进虚空 |

## 3. 根因：代码链路

### 3.1 报名时把「当前世界」存成返程点

`SeasonService#registerLocal`（约 L240–250）：

```java
Location loc = p.getLocation();
registrations.add(new SeasonRepository.Entry(
        event.id(), p.getUniqueId(), guild.id(), plugin.serverId(),
        loc.getWorld().getName(),          // ← 副本实例世界也会被存进来
        loc.getX(), loc.getY(), loc.getZ(), loc.getYaw(), loc.getPitch(), "REGISTERED"));
```

单服工会战同款逻辑在 `WarManager#originOf`（约 L2669）：

```java
Location loc = player.getLocation();
return new WarOrigin(war.id(), player.getUniqueId(), localServerName(),
        loc.getWorld() == null ? "" : loc.getWorld().getName(), ...);
```

liudungeon 的实例世界名形如 `ld_<模板>_<32位十六进制>`，生命周期 = 一次副本；副本结束就**卸载并删除**。把它存成返程点，等于存了一个必定失效的地址。

### 3.2 每 5 秒轮询一次「待返程」

`SeasonService#tick`（L117）：

```java
long pollInterval = current == null ? 5000L : 1000L;
...
var returns = repo.pendingReturns();
for (var entry : returns) returnPlayer(entry);
```

`SeasonRepository#pendingReturns`（L100）取的是「赛事已结束但 `state <> 'RETURNED'`」的记录——只要状态不变，就会一直被取出来。

### 3.3 世界不存在时只发消息、不清记录

`SeasonService#returnPlayer`（L490–492）：

```java
World target = WorldResolver.resolve(entry.world());
if (target == null) {
    p.sendMessage("§c赛季返程世界未加载：" + entry.world() + "，保留返程记录。");
    return;   // ← 记录保留 ⇒ 5 秒后又来一遍 ⇒ 世界名进聊天、永远回不去
}
```

### 3.4 非承办服每轮发一次代理 Connect

同函数：

```java
if (!plugin.war().isHostServer(entry.source())) {
    transferCooldown.remove(entry.player());
    transfer(p, entry.source());   // ← 每轮 Connect fb
    return;
}
```

被封禁后每次连接都被 fb 拒绝，客户端就变成「无法连接至 FB。您已被此服务器封禁」。

### 3.5 附带的传送封印

`SeasonService#teleport`（L568）与 `#command`：

```java
@EventHandler(ignoreCancelled = true)
public void teleport(PlayerTeleportEvent e) {
    if (restricted(e.getPlayer().getUniqueId()) && !plugin.war().isAllowingWarTeleport(...)) {
        e.setCancelled(true);   // ← 玩家「传送不走」的直接原因
    }
}
```

### 3.6 同源的第二处坑：工会战赛后返程

`WarManager` 赛后同服返程（约 L4477）：

```java
Location destination = origin != null
        ? new Location(Bukkit.getWorlds().isEmpty() ? null : Bukkit.getWorlds().get(0),
                origin.x(), origin.y(), origin.z(), origin.yaw(), origin.pitch())  // ← 旧坐标 + 主世界
        : returnLoc.get(uuid);
```

世界解析失败时仍沿用旧坐标 ⇒ 把副本里的 y 值套到主世界 ⇒ 空中/虚空掉落（正是 L11808 的 `fell out of the world`）。
`teleportToOriginLocal`（L2744）有同样问题：世界解析不到时用主世界，但仍用 `origin.x/y/z`。

## 4. 修复方案

> **最小改动 = P2**。只改 P2 即可止血：老记录会在玩家下次上线时自动修好、不再刷屏、不再被往 fb 送。
> P1/P3/P4 用于掐断源头，建议一起发版。

### P1. 工具方法（`util/WorldResolver.java`）

import 区补 `import org.bukkit.Location;`，在 `normalize()` 之前插入：

```java
/** 动态创建、随时会被删掉的临时世界名（liudungeon 副本实例 / 外部竞技场）。 */
public static boolean isTransientWorld(String configured) {
    if (configured == null || configured.isBlank()) {
        return true;
    }
    String name = keyName(configured.trim()).toLowerCase(Locale.ROOT);
    return name.startsWith("ld_") || name.startsWith("ldext_");
}

/** 兜底落点：跳过临时世界后第一个已加载世界的出生点；没有则 null。 */
public static Location defaultSpawn() {
    for (World w : Bukkit.getWorlds()) {
        if (!isTransientWorld(w.getName())) {
            return w.getSpawnLocation();
        }
    }
    return null;
}
```

可选（更严谨）：LiuGuild 已软依赖 liudungeon（`libs/liudungeon-1.9.3.jar` 中 `TemplateManager.isInstanceWorldName` 为 `public static`），可在 `DungeonHook` 里加：

```java
public boolean isTransientWorld(String name) {
    try {
        return com.liu.liudungeon.world.TemplateManager.isInstanceWorldName(WorldResolver.keyName(name));
    } catch (Throwable t) {
        return WorldResolver.isTransientWorld(name);
    }
}
```

注意 `plugin.dungeon()` 可能为 `null`，所以 `WorldResolver` 的前缀判断必须保留作兜底。

### P2. `SeasonService#returnPlayer` 加兜底 + 提示限流（核心）

字段区（紧挨 `transferCooldown`）新增：

```java
/** 返程失败提示限流（UUID → 上次提示时间），避免 5 秒轮询把聊天刷爆。 */
private final Map<UUID, Long> returnNoticeAt = new HashMap<>();
```

`quit(PlayerQuitEvent)` 中补一行：

```java
returnNoticeAt.remove(event.getPlayer().getUniqueId());
```

整段替换 `returnPlayer`：

```java
private void returnPlayer(SeasonRepository.Entry entry) {
    Player p=Bukkit.getPlayer(entry.player());
    if(p==null || p.isDead() || restricted(entry.player()) || restoring.contains(entry.player()) || plugin.war().isWarRestricted(entry.player())) return;
    if(plugin.sparrow()!=null && !plugin.sparrow().playerReady(entry.player())) return;
    // 必须确认托管已归还，才允许跨服离开。
    if(System.currentTimeMillis()-transferCooldown.getOrDefault(entry.player(),0L)<3000) return;
    transferCooldown.put(entry.player(),System.currentTimeMillis());
    submit(() -> {
        try {
            var latest=repo.entry(entry.event(),entry.player());
            if(latest==null || "RETURNED".equals(latest.state()) || !latest.source().equals(entry.source()) || !latest.world().equals(entry.world())) return;
            if(plugin.repo().loadWarEscrow(entry.player())!=null) { plugin.sync(() -> {
                plugin.war().recoverPendingEscrow(p);
                // 恢复模块异步完成后才继续返程，恢复原始无敌状态由赛季清理兜底。
                plugin.syncDelayed(() -> { if(p.isOnline() && !restricted(entry.player())) p.setInvulnerable(false); },20);
            }); return; }
            plugin.sync(() -> {
                if(!p.isOnline() || restricted(entry.player())) return;
                if(!plugin.war().isHostServer(entry.source())) {
                    transferCooldown.remove(entry.player()); transfer(p,entry.source()); return;
                }
                // 原世界还在 → 精确回原坐标；世界已被删（副本实例/临时竞技场）→ 退回主城出生点。
                // 旧实现只发一句"保留返程记录"就 return，记录永远不清：每 5 秒刷屏、每次登录重来。
                Location dest=returnDestination(latest);
                if(dest==null) { noticeReturnFailed(p,latest.world()); return; }
                boolean ok;
                try { ok=plugin.war().warTeleport(p,dest); }
                catch (Throwable t) { plugin.getLogger().warning("赛季返程传送异常: "+t.getMessage()); ok=false; }
                if(ok) {
                    submit(() -> { try { repo.entryState(entry.event(),entry.player(),"RETURNED"); } catch(Exception e) { failure(e); } });
                } else {
                    noticeReturnFailed(p,latest.world());
                }
            });
        } catch(Exception e) { failure(e); }
    });
}

/** 返程落点：世界有效就用原坐标，失效就回主城出生点（绝不把旧坐标套到别的主世界）。 */
private Location returnDestination(SeasonRepository.Entry entry) {
    World target=WorldResolver.resolve(entry.world());
    if(target!=null) return new Location(target,entry.x(),entry.y(),entry.z(),entry.yaw(),entry.pitch());
    Location fallback=WorldResolver.defaultSpawn();
    if(fallback==null) return null;
    plugin.getLogger().warning("赛季返程目标世界已失效（"+entry.world()+"），"+entry.player()+" 改送回 "
            +fallback.getWorld().getName()+" 出生点。");
    return fallback;
}

/** 同一条失败提示 60 秒最多一次；成功兜底返程后记录会被标成 RETURNED，循环自然停止。 */
private void noticeReturnFailed(Player p,String world) {
    long now=System.currentTimeMillis();
    Long last=returnNoticeAt.get(p.getUniqueId());
    if(last!=null && now-last<60_000L) return;
    returnNoticeAt.put(p.getUniqueId(),now);
    p.sendMessage("§c赛季返程失败：目标世界 §f"+world+" §c已不存在，已改送回主城出生点；若仍失败请联系管理。");
}
```

`SeasonService` 已 `import com.liu.liuguild.util.WorldResolver;` 与 `org.bukkit.*`，无需追加 import。

### P3. 报名时不要记录临时世界（`SeasonService#registerLocal`）

替换循环体：

```java
for(Player p:players) {
    Location loc=p.getLocation();
    boolean transientWorld=loc.getWorld()==null || WorldResolver.isTransientWorld(loc.getWorld().getName());
    // 身在副本/临时世界：那是"用完即删"的世界，记成返程点赛后必然失效。
    // 改记主城出生点；连主城都没有就跳过，别造一条注定失败的记录。
    if(transientWorld) {
        Location spawn=WorldResolver.defaultSpawn();
        if(spawn==null) continue;
        loc=spawn;
    }
    registrations.add(new SeasonRepository.Entry(event.id(),p.getUniqueId(),guild.id(),plugin.serverId(),
            loc.getWorld().getName(),loc.getX(),loc.getY(),loc.getZ(),loc.getYaw(),loc.getPitch(),"REGISTERED"));
    p.sendMessage("§6[工会赛季] §e已报名混战，正在等待参赛名单汇总。");
}
```

> 另一种取向：`if(transientWorld) continue;` —— 在副本里的人干脆不报名（不打断打本）。二选一，不要两样都做。

### P4. `WarManager` 的三处同类问题

**(a) `originOf()`：出发地不记临时世界**

```java
private WarOrigin originOf(Player player, GuildWar war) {
    if (player == null || war == null) {
        return null;
    }
    Location loc = player.getLocation();
    if (loc.getWorld() == null || WorldResolver.isTransientWorld(loc.getWorld().getName())) {
        // 副本实例世界会后删：记它等于让赛后返程必失败。
        Location spawn = WorldResolver.defaultSpawn();
        if (spawn == null) return null;
        loc = spawn;
    }
    return new WarOrigin(war.id(), player.getUniqueId(), localServerName(),
            loc.getWorld().getName(), loc.getX(), loc.getY(), loc.getZ(), loc.getYaw(), loc.getPitch());
}
```

**(b) `teleportToOriginLocal()`：世界解析不到时只回出生点**

```java
private void teleportToOriginLocal(Player player, WarOrigin origin) {
    World world = origin.world() == null || origin.world().isBlank()
            ? null : WorldResolver.resolve(origin.world());
    Location target;
    if (world != null && origin.world() != null && !origin.world().isBlank()) {
        target = new Location(world, origin.x(), origin.y(), origin.z(), origin.yaw(), origin.pitch());
    } else {
        target = WorldResolver.defaultSpawn();   // 世界没了：只回出生点，别把旧坐标套上去
        if (target == null) return;
        plugin.getLogger().warning("工会战返程世界已失效（" + origin.world() + "），改送回主城出生点。");

    warTeleport(player, target);
```

## 5. 数据救援（可先做，补丁上线后也会自愈）

排查还有谁挂着：

```sql
SELECT e.event_id, e.player, e.world, e.state
FROM season_entries e                        -- MySQL: liuguild_season_entries
JOIN season_events s ON s.id = e.event_id    -- MySQL: liuguild_season_events
WHERE s.state IN ('FINISHED','CANCELLED') AND e.state <> 'RETURNED';
```

放行受影响玩家（`_Elio_OvO` 的 UUID 取自 fb 日志 L11548）：

```sql
UPDATE season_entries SET state='RETURNED'
WHERE player IN ('78af915e-e154-3b28-a374-a6c2806e4d4a')
  AND state <> 'RETURNED';
```

说明：

- 表名规则见 `db/Database#t`：SQLite 无前缀，MySQL 为 `liuguild_<name>`。
- 线上 fb 的 LiuGuild 走 `/mc/shared/LiuGuild-config` 共享配置，实际是 SQLite 还是 MySQL 以该机 `database.yml` 为准。
- Redis 里的 `liuguild:war:pending:*` / `war:return:*` 都是短 TTL（180s / 300s），一般无需清理。

## 7. 经验与后续

1. **不要把「玩家当前所在世界」无条件当持久坐标存库**：任何「动态创建、用完即删」的世界（副本实例、临时竞技场、动态世界）都必须先判定，再决定存原坐标还是存主城落点。
2. **「保留记录 + 定时重试」必须配终止条件**：重试可以，但要有兜底落点、要有提示限流、要能在必要时放弃。否则一条坏记录 = 玩家永久卡死。
3. 失败提示不要硬编码在逻辑里（当前 `SeasonService#returnPlayer` 直接 `sendMessage` 中文），建议挪进 `messages.yml`。
4. liudungeon 文档可补一条：`ld_*` 是可随时删除的临时世界，其他插件**不要**持久化其坐标（当前 `docs/05-使用说明/01-它是什么.md` 未提及）。

## 8. 代码落地状态

本次已按 P1–P4 落地：

- `WorldResolver` 增加 `isTransientWorld` / `defaultSpawn`，识别 `ld_*`、`ldext_*` 临时世界并跳过它们选择主城出生点。
- 赛季报名遇到副本/临时世界时改记主城出生点。
- 赛季返程世界失效时改送主城出生点并写 `RETURNED`；同一条记录不再每 5 秒重试、刷屏或反复 Connect；失败提示 60 秒限流。
- 工会战出发地不记录临时世界；同服返程世界失效时只回主城出生点，returnLoc 也不再把旧坐标套到主世界。
- 赛季返程成功改送主城出生点时给玩家一次提示，日志记录一次目标世界失效。

验证：`mvn test` 304 个测试通过。仍需在真实 Paper/Velocity 多服环境验证世界卸载时序、代理传送与玩家实际落点。
