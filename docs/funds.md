# 资金与金币

## 三种余额

| 余额 | 来源 | 用途 |
|---|---|---|
| 个人工会资金 | 每日签到的 points 奖励 | 自愿捐献给当前工会，离会保留 |
| 公共工会资金（原 points） | 个人捐献、工会战、在线活跃及其他原有公共奖励 | 工会建设、仓库续期与容量升级等既有资金消耗 |
| 工会金币（原 bank） | 玩家存入 Vault 金币 | 银行按既有权限存取 |

资金不是 Vault 金币，不能提现，不能兑换金币。金币存入银行不等于捐献建设资金。
商店购买使用<b>个人工会资金</b>支付，税后货款进入<b>公共工会资金（点数）</b>，与工会金币无关。

## 玩家操作

主菜单 → **工会资金 · 捐献**：查看个人资金、公共资金和工会金币说明；点击个人资金按钮输入正整数即可捐献。捐献不可撤回，公共资金不会退给退会玩家。

个人资金存于独立的 `personal_funds` 表，以玩家 UUID 为键。个人扣款、工会入账在同一 SQL 事务提交，数据库检查余额、成员身份和溢出。签到领取以玩家和日期判重，换服或退会重入不能重复领取当天个人资金。

## 战令任务

成功捐献会触发 `GuildFundsEvent`（`Action.DONATE`），并向 liupass 上报 `liuguild:donate`，**进度为捐献金额**（开关 `hooks.liupass.donate`）。
可据此配置「累计捐献 N 资金」类任务，详见 [tasks.md](tasks.md)。

## 升级兼容

- 原公共 points 和 bank 保持原值；不自动拆分、兑换或分配给成员。
- 新个人资金账户初始为 0；更新后签到奖励进入个人资金，不再直接进入公共资金。
- 工会战和在线活跃仍按原规则奖励公共资金；没有额外复制一份个人奖励。
- 自动建表关闭的部署需由管理员根据 `Database.createTables()` 补建新表。
- 全部子服应停服同时更新，避免旧版签到与收购行为继续运行。

## GUI

工会列表默认每页 28 项，四行七列并保留四周留白；条目只展示等级、人数与加入方式，完整内容通过右键详情查看。商店同样每页 28 项并支持翻页。内置菜单在配置缺少返回按钮时有底栏返回兜底；主菜单提供关闭按钮。

自定义 `gui.yml` 需同步新 `funds` 按钮和精简后的列表 lore，尤其检查 `overrides/` 是否覆盖默认布局。Sparrow 主菜单使用同一按钮配置和动作映射。
