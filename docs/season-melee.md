# 多工会赛季混战

## 当前实现范围

`season` 模式使用独立混战控制器；自定义模式可设置 `season.melee: true`。
管理员 `/guildadmin war start season` 或赛季时间表触发报名。

- `season.registration-seconds`（默认15秒）跨服报名汇总，之后进入准备阶段（至少15秒）。
- 每工会按最低等级、人数、队伍上限筛选；入场前持久化装备托管。
- 套装与公平血量遵循该模式的 `fair-equipment`、`fair-health` 配置：关闭 `fair-equipment` 时保留玩家自带装备，关闭 `fair-health` 时不屏蔽蟠桃血量。
- 所有工会进入同一场地。按工会ID排序分配点位，不足循环复用。
- 击杀按 `score.kill` 加分，不扣死亡分；总分降序、死亡数升序，完全相同并列（1、1、3）。
- 使用每人生命次数，复活等待仍算存活；断线淘汰。
- 时间到或剩余存活工会不超过一个时结算。
- BossBar显示前五名，参赛者 `/guild war status` 查看完整即时排名。
- `season.rank-rewards` 按名次奖励公共工会资金。默认前三名5000/3000/1000，显式配置替换默认；不使用双队胜负奖励。
- 排名记录、资金入账与比赛终态同事务保存，重试不重复发奖。
- 自动返回出发服务器和坐标；可配置 `after-war.end-spawn.server/world/x/y/z/yaw/pitch` 覆盖赛后目的地。
- 跨服状态通过共享数据库轮询，使用已有代理 Connect 通道切服，无需新代理插件。
- 承办服重启取消残留赛事，不继续中断比赛；90秒无心跳取消，保留装备和返程恢复依据。

## 限制和验证边界

支持固定世界、内置临时世界和 liudungeon 模板场地；场地创建失败取消赛事，不会静默回退。
各子服必须使用同一数据库和表前缀；`server-id` 必须等于代理登记名。

单元测试覆盖排名、生命、循环点位、报名数据持久化、玩家跨赛事互斥、承办服互斥和幂等奖励；尚未进行真实Paper/Velocity/SparrowSync多服验证。
已加入玩家数据 ACTIVE 会话检测、断线淘汰、托管保存后才发装备以及终态返程记录。真实玩家交互、数据库故障注入与多服完整往返仍需联调验证；测试通过不代表这些环境行为已得到实测确认。
