# 玩家在线活跃 → 工会资金

把「玩家真的在玩」变成工会资金收入：每隔一段时间，按每个工会的**活跃在线成员数**发放工会资金，是签到、工会战之外的第三条工会资金来源。

> 工会资金即本插件的 `points`，与工会银行（Vault 金币）分开。

## 配置（`guild.yml`）

```yaml
guild:
  activity:
    enabled: true          # 总开关
    interval-seconds: 300  # 结算间隔（秒，至少 30）
    points-per-player: 2   # 每个活跃在线成员每次结算贡献的工会资金
    daily-cap: 1000        # 每个工会每天最多获得（0 = 不限）
    afk-seconds: 180       # 多久没操作算挂机（秒，0 = 不检测，纯在线即算）
    min-online: 1          # 至少需要多少名活跃成员才结算（0 = 有 1 名即可）
```

一次结算：`发放 = 活跃在线人数 × points-per-player`，且每个工会每天累计不超过 `daily-cap`。

## 「活跃」怎么判定

只按在线时长发钱，挂机党会白嫖。这里用事件记录每个玩家的**最近活跃时间**，结算时只统计在 `afk-seconds` 内动过的成员：

| 计入活跃的操作 |
|---|
| 移动到不同方块（只转视角不算） |
| 左/右键交互、破坏/放置方块 |
| 受到伤害、攻击实体 |
| 钓鱼 |
| 进入服务器（登录时按活跃计一次） |

活跃时间的写入做了 1 秒节流，高频事件不会造成额外开销。把 `afk-seconds` 设为 `0` 即可退化为「纯在线即算」。

## 每日上限与跨服

- `daily-cap` 按**工会 + 自然日**统计，实际上限判定在**数据库内原子完成**（读当日已发额 → 算本次可发额 → 乐观锁写入），多台子服同时结算也不会超发。
- 结算任务在**主线程**按间隔执行；配置热重载会按新间隔重启任务。
- 发放后通过 `GUILD_CHANGED` 广播通知其它子服刷新缓存，积分/等级（按点数重算）在各服保持一致。
