# 生产环境审查与修复报告（2026-10-26）

## 结论

本轮审查覆盖工会战生命周期、掉线重连、装备托管、商店交易、数据库并发写入、配置/Redis 生命周期、GUI 与可选钩子。已修复会导致刷物品、丢装备、跨服状态残留、内存/数据库分裂和界面越界的高风险问题。

代码层验证：`mvn test` 通过 **316 个测试，0 失败、0 错误**。测试属于 JUnit/源码守卫与 SQLite 仓储测试，**不等同于 Paper 服务器、真实代理、Redis 多服和真实客户端的集成验收**；上线前仍应在测试服完成一次完整开战/掉线/重连/结算回归。

## 高风险问题与修复

### 1. 工会战掉线、重连与结束

- 掉线参赛者保留 roster 与剩余生命，在 `war.reconnect-seconds` 宽限内重登会自动回到承办服并重新入场。
- 跨服重登通过 `war:reconnect:<uuid>` 标记转送承办服；代理传送失败或 30 秒未切服会清除标记，避免之后正常进服被误拉入战局。
- 宽限到期仍掉线者标记淘汰；某方无存活者时立即结束战局，不再拖到比赛时长结束。
- `war.enabled=false` 热重载不会中断已有场次：已有 session 时继续调度 tick，保证倒计时、结算和返程能走完。
- 结束事件新增 `OTHER_WIN` 与真实 `winnerGuildId`；N 公会混战的 C/D 公会夺冠不再被误报为 A 胜。任务奖励遍历全部 party，不再只发 A/B。

### 2. 装备托管与刷装备

- `guild_war_escrow` 改为 **insert-only**：已存在未恢复托管时拒绝入场，绝不覆盖上一场遗留的玩家原装备。
- 入口快照编码失败、写库失败、写库后状态失效都会清理本场 roster/临时状态；写库后未发套装的托管按 `war_id + created_at` 条件删除，避免异步清理误删玩家刚重新入场的新快照。
- 赛季入场在异步写库期间结束时，同样删除未生效托管，而不是用旧背包快照覆盖玩家当前物品。
- 托管恢复统一走 `recoverPendingEscrow`；只有已真正发放套装/改写背包的托管才允许恢复。
- 合成栏/快捷栏：入场前清理 2x2 合成栏并选择首个非空快捷栏槽位，配合现有源码守卫测试防止套装带出/空手判定。

### 3. 商店复制与交易不确定状态

- 上架/下架/购买都记录操作前背包精确快照，崩溃恢复用 `Arrays.equals` 判断物品是否已扣除/发放，不再用数量推断。
- 购买发货和删除交接记录不再“先删后发”；恢复时仅在背包等于操作前快照时补发，否则转人工复核，避免重复发货。
- 下架要求背包能完整放下库存；不再掉落物品，从而保留可判定的补发条件。
- 数据库异常可能发生在 COMMIT 之后：购买/下架保留交接记录并触发自动核对，不再一律删除记录导致“已扣款未发货/物品消失”。新增 `shop-purchase-uncertain`、`shop-remove-uncertain` 提示。
- 上架/下架/改价成功消息只在写库成功后发送；消除重复错误提示。GUI 改价失败恢复旧价并给出失败反馈。

### 4. 数据库一致性与并发写入

- 会长转让改为一个事务：`guilds.leader_*` 与新旧成员 rank 同时更新，并以旧会长为条件；并发转让只有一方成功。
- 整行 `saveGuild` 不再携带 `leader_uuid/leader_name/wins/losses`，避免其它子服旧快照覆盖刚完成的转让/战果；胜/负改为原子 `+1`。
- 退会/踢人删除带 `joined_at` 代际守卫，旧删除不会误删刚重入会的新成员关系。
- 关服补删顺序修正：先 `flushAll`，再补成员删除；解散/成员删除失败后每 30 秒自动重试，不再只等关服。
- 老库 `member_count` 启动时按真实成员关系回填，避免人数上限被 0 绕过。
- 修复成员缓存、工会索引和 pending 删除之间的竞态；`removeMember` 对已并发移除的成员直接返回，避免误伤重入会记录。

### 5. 配置、Redis 与生命周期

- `ConfigManager` 使用不可变快照同时发布 files + Settings；解析/消息重载失败不会留下半新半旧配置。指纹混合存在性、文件名、长度和 mtime，可感知删除/同名替换，且不被配置目录噪声误触发。
- 跨服连接参数（`server-id`、`cross-server.*`、`transfer.enabled`）在启动时固化；热重载在发布前冻结回旧值并警告需重启，避免新配置与旧连接撕裂。
- Redis 启动失败后每 30 秒自动重连；降级状态通过 PING 探针恢复；订阅断开时 `ready=false`，重连成功再置位。
- 多服模式下 Redis 不可用时，全局清理/历史保留任务直接跳过；单服模式才允许本地执行，避免所有子服重复清理。
- 关闭顺序改为：释放仓库 Redis 锁 → 停跨服总线 → 停模块；仓库锁心跳给 Redis 抖动 3 次宽限，锁确实失效才立即踢出。
- 历史数据保留任务独立于 `cleanup.enabled`，每 6 小时执行一次，多服用 Redis 抢锁。

### 6. 可选钩子、GUI 与输入安全

- Vault 经济钩子改为纯反射，Vault 缺失时也始终返回非空实例；无经济语义为“检查放行、扣款成功、存款失败、余额 0”。
- mcMMO 与宠物钩子始终注册，开关 `hooks.mcmmo.block-in-war` / `hooks.pets.block-in-war` 在事件/tick 中实时读取；改配置后不需要重启才生效。
- 竞技场 id、套装 key 统一校验 `[a-z0-9_-]{1,32}` 并小写化，避免任意字符串写入配置路径。
- GUI 按钮槽位按实际 inventory size 夹取，越界时跳过并告警，不再因 rows 调小而抛 AIOOBE；Sparrow 会话在玩家退出时清理。
- 聊天输入会话增加 60 秒超时；GUI 异步回调统一回主线程，玩家离线时不再操作库存。
- 管理面板删除竞技场走聊天确认；`war stop <id>` 拼写错误不再回退误停赛季/当前战局；`setlevel/setpoints` 在数据库失败时给出明确反馈并回滚/钳制。
- 工会公告/简介写入前做 MiniMessage 可解析性校验，渲染侧畸形文本降级为转义纯文本，单个工会公告不再拖垮成员 GUI。
