# 已知问题

## 工会战准备阶段切换快捷栏后仍按空手判定

- **状态**：待实测 / 仍未确认完全修复
- **现象**：空手进入准备阶段，切到钻石剑，开战后攻击仍可能按空手结算，需要再切一次快捷栏。
- **已做处理**：
  - `PacketEventsHook` 不再取消 `HELD_ITEM_CHANGE`，允许准备阶段同步快捷栏槽位。
  - 仍保留移动、攻击、交互、挖掘、放置、使用物品等包级锁定。
- **待确认**：
  - 0.4.6 在真实客户端 + PacketEvents 环境下复测。
  - 若仍复现，需要记录客户端切槽时服务端 `PlayerItemHeldEvent`、`Inventory.getHeldItemSlot()` 和开战瞬间的 held slot。
- **临时规避**：开战后手动切换一次快捷栏。

## 赛后返程位置理解差异

- 当前代码记录的是**切服/入场前**的玩家位置；不是更早的排队前位置。
- 如果玩家先被其他插件传送到集合点再匹配，返程会回集合点。
- 若要严格回到“点击匹配前”的位置，需要在排队时额外记录坐标，当前未实现。
