# 僵尸工会清理

用于定期或手动清理长期无人活跃的“僵尸工会”。

## 判定标准

一个工会被判定为**不活跃**，需要**同时满足**：

1. 当前**没有任何成员在线**；
2. 距离**最后一次活跃**已超过 `inactive-days` 天；
3. （可选）成员数不超过 `max-members`（设为 0 表示不限制）。

「最后一次活跃」会在以下时机更新：

- 有成员登录服务器（写库做 1 小时节流，避免频繁写盘）；
- 工会数据发生变化（创建、加入、退出、银行、点数、等级等）。

> 因此只要有人上线或工会有任何变动，该工会就不会被清理。

## 配置（guild.yml）

```yaml
guild:
  cleanup:
    enabled: false         # 自动定期清理总开关（默认关闭）
    inactive-days: 30      # 连续多少天无活动且无人在线
    interval-minutes: 360  # 自动检查间隔（分钟）
    max-members: 0         # 仅清理成员数不超过该值的工会（0 = 不限）
    dry-run: false         # 试运行：只记录不删除
    broadcast: true        # 删除时是否全服广播
```

建议先用 `dry-run: true` 观察一段时间，确认判定符合预期后再关闭试运行。

## 手动执行（管理员）

| 指令 | 说明 |
|---|---|
| `/guildadmin cleanup` | 扫描并按当前配置列出将被清理的工会（**不会删除**） |
| `/guildadmin cleanup dry` | 同上，显式试运行 |
| `/guildadmin cleanup confirm` | 真正执行删除 |

输出示例：

```
===== 不活跃工会清理 =====
判定：连续 30 天无活动且无人在线
模式：试运行（未删除） 命中：2
- 幽影议会 [幽影] 成员=3 最后活跃=45 天前
- 旧日同盟 [旧日] 成员=1 最后活跃=120 天前
确认删除请执行：/guildadmin cleanup confirm
```

## 行为

- 删除工会会同时清理其成员关系与工会驻地（`guild_homes`）。
- 触发 `GuildDisbandEvent`，`cause` 为 `INACTIVE`，便于其它插件监听。
- `broadcast: true` 时按解散广播提示；`false` 时静默删除。
- 自动清理任务在关闭插件时会一并取消。
- 战报/奖励/邮件/申请/审计等历史数据由独立的保留任务每 6 小时清理（多服用 Redis 抢锁），
  不受本页 `cleanup.enabled` 影响。
